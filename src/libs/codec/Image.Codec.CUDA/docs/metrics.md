# 画质指标（MSE / PSNR / SSIM / MS-SSIM）

编解码库里必须有画质指标，理由是「压得多小」只有和「画质降了多少」一起看才有意义。
调参（`Image.Codec.CUDA::Tune`）也用同一套指标做候选校验——否则「这条参数更快」可能只是
因为它把画质压坏了。

指标与编解码同级提供，而不是让每个调用方各写一遍：写法一不一致，数字就没法横向比较。

## 精确定义

设两张同尺寸、同通道数的图 `x`、`y`，`N = 宽 × 高 × 通道数`。

```
MSE  = Σ(x-y)² / N
PSNR = 10·log10(255² / MSE)          MSE == 0 时固定 99.0
```

`MSE == 0` 返回 99.0 而不是 `Inf`：`Inf` 会污染平均值、JSON（`Inf` 不是合法 JSON）和排序比较。
「无损」用 99 dB 表达足够（它已经明显高于任何有损编码的结果）。

### SSIM

对每个 **(像素, 通道)** 计算，再对全部样本取均值：

```
SSIM = ((2·μx·μy + C1)(2·σxy + C2)) / ((μx² + μy² + C1)(σx² + σy² + C2))
```

- 窗：**11×11 高斯**，σ = 1.5（一维权重归一化后取外积）；
- 边界：**复制边缘**（replicate）。`valid` 策略会让小图少掉一圈样本、不同尺寸的图之间
  不可比，所以不用；
- 常数：`C1 = (0.01·L)²`、`C2 = (0.03·L)²`、`L = 255`；
- 通道：逐通道各自计算后取均值（不做 RGB→灰度转换，避免引入一个会因后端而异的颜色公式）。

### MS-SSIM

5 级金字塔，每级 2×2 **均值**下采样（`floor(w/2) × floor(h/2)`，与 `avg_pool2d(2)` 一致；
**不是** `imresize` 的双三次——后者会引入负值与振铃，让不同实现对不上）：

```
MS-SSIM = Π_{j<M-1} CS_j^w_j · SSIM_M^w_{M-1}
```

`w = {0.0448, 0.2856, 0.3001, 0.2363, 0.1333}`（Wang 等 2003）。

两点实现约定：

1. **逐级降低的尺度数**：第 `M` 级仍需 ≥ 11×11 才能算 11×11 窗，所以小图会少于 5 级
   （`levels` 字段回填实际级数）。
2. **权重归一化**：标准 5 个权重之和是 **1.0001**（不是 1）。少于 5 级时直接把前 M 个权重
   连乘会让小图的 MS-SSIM 系统性偏小，因此实现里把用到的前 M 个权重归一化到和为 1。
   注意：负 CS（强反相关区域）会让 `pow` 无定义，此时返回 0。

## 入口

```
mse(a, b, opt, &value)              // 只有减法和平方
psnr(a, b, opt, &value)             // 内部就是 mse()
ssim(a, b, opt, &{ssim, ms_ssim, levels})
```

为什么 SSIM 与 MS-SSIM 合成一个入口：**MS-SSIM 的第 0 级就是 SSIM 的那次统计**。
拆成两个函数只有两种结果——要么把最贵的第 0 级算两遍，要么其中一个偷偷调另一个。

为什么 MSE 不并进去：11×11 窗的内存流量是纯平方误差的**上百倍**。只要 MSE 的调用方
（例如快速筛掉编码器坏输出）不该白付这笔钱。

## 实现形态（大图友好）

两张 32000×19656×3 的图同时驻留显存就是 3.8 GB，再加 SSIM 中间量必然 OOM。所以：

- **按行 band 流式上传**：显存占用 = `(band_rows + 2·halo) × 行字节`，与图像高度无关；
  两端的越界行在 host 侧复制边缘行后一起上传，kernel 里不再判边界。
- **不做「先可分离模糊成 5 张 float 平面再合成」**：那需要 5 张与图等大的 float 平面
  （同一张图就是 12.5 GB）。直方窗口每像素 2×121 次读，全部命中 L2，实测远便宜。
- **金字塔不整座保留**：只保留当前层与下一层的 host 缓冲，否则 1.9 GB 的图会白占约 630 MB。

## 正确性如何验证

`tests/codec_roundtrip_test.cpp` 里有三类检查：

1. **GPU vs CPU 参考实现**：`band_rows = 16` 的多 band 路径逐项对拍（容差 1e-9）。
   band 越小，halo 拼接与归约次数越多——边界错一位会立刻暴露。
2. **解析解**：常数图对 σ = 0，CS 恒为 1，SSIM 退化成亮度项，可以与手算值逐位比较。
   这是唯一不依赖「另一份实现」的检查：对拍只能证明两边一致，证明不了两边一起错。
3. **自反性**：同一张图与自己的 MSE = 0、PSNR = 99、SSIM = MS-SSIM = 1。

## 跨后端一致性（硬性）

Image.Codec.Offload 的 OpenCL / Vulkan / CUDA 三个后端**必须给出相同的数字**，否则
「换了后端画质变了」这种结论无从判断。要求：

- 常数、窗、边界策略、金字塔方式各只有一份定义（`metrics_common.h` 及其同源副本）；
- kernel 里的加权和用 **double** 累加（用 float 会让均值化的 SSIM 差到 1e-6 量级，
  只能靠放宽容差来「通过」，那不是对齐）；
- 不要为了某条路径「更简单」而改动定义。
